# FixWise

A safety-first AI appliance troubleshooting MVP built with Next.js, TypeScript, Zod, and an optional Groq/Supabase integration.

## Run locally

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open `http://localhost:3000`. No credentials are required: the app uses a deterministic local diagnostic engine and localStorage session history.

## Live AI mode

Add `GROQ_API_KEY` to `.env.local`, then restart. `/api/diagnose` automatically switches to `llama-3.3-70b-versatile`, validates structured output with Zod, and runs a second safety audit on repair steps. If Groq fails, the request falls back to the local engine rather than losing the session.

The current upload UI validates and previews appliance images. Wiring image bytes to a currently available Groq vision model is deliberately isolated as the next adapter task because the model name in the original specification is a preview model and may no longer be available.

## Persistence

The zero-config MVP persists sessions in localStorage. To enable Supabase, create a project, run `supabase/schema.sql`, configure `.env.local`, and replace the `save`/`load` functions in `app/diagnose/page.tsx` with Supabase queries. The schema includes row-level security.

## Safety layers

1. Regex input filter runs before any model call.
2. The reasoning prompt prohibits hazardous repair categories.
3. Zod validates every response shape.
4. A deterministic output scan catches known unsafe instructions.
5. Live Groq mode adds an independent LLM output audit.
6. Emergency copy is hardcoded and never generated by the model.

## Key routes

- `/` — responsive editorial landing page
- `/diagnose` — diagnosis shell, uploads, multi-turn chat, results, history
- `/api/diagnose` — filter → reason/fallback → validate → safety scan
